# CLAUDE.md — Lil Buddy

## What this is

**Lil Buddy** (`lil <prompt>`) is a quick-access terminal sysadmin assistant: a
shell function that fires a one-shot [pi](https://github.com/earendil-works/pi)
run on DeepSeek V4 Flash with a Pip-Boy-flavored sysadmin persona, shows a live
panel while it works, streams a terse answer, and — when the answer is a
runnable command — drops into an interactive scratchpad (run / copy / edit /
dismiss / follow-up). It is a *reference guru*, not a coding agent; other
workflows own code generation. macOS and Linux; zsh, bash and fish.

## Architecture (one pass)

```
lil <prompt>                    shell function (shell/lil.{zsh,bash,fish}) or bin/lil
  └─ node src/cli.mjs           the engine — plain ESM, zero npm dependencies
       ├─ platform.mjs   snapshots ($LIL_RUNTIME/clip.txt, term.txt), fingerprint
       │                 (24h cache), clipboard, OS / terminal / Nerd Font detection
       ├─ pi.mjs         spawn pi --mode json; EventTranslator → stage / thinking /
       │                 text / tool_start / tool_end / usage; replay() for --demo
       ├─ render.mjs     markdown → ANSI (Renderer, AnswerStream), scratchpad box
       ├─ lilcmd.mjs     the answer contract: last ```lilcmd / <lilcmd> block
       ├─ update.mjs     daily background fast-forward of the checkout; --update
       ├─ ui/panel.mjs   the live panel (speech, thought ticker, tools, meta)
       ├─ ui/sprite.mjs  Lil Buddy: 16×12 half-block pixels, moods, CRT power
       ├─ ui/decrypt.mjs the RobCo decryption line
       ├─ ui/term.mjs    Live (redrawable region) + Keys (raw key reader)
       └─ app.mjs        one invocation: turn → scratchpad → handoff
```

Key design facts:

- **The engine is a subprocess; "run" is a handoff.** RUN must execute in the
  user's interactive shell (aliases, cd, history), which a child process
  cannot do. The shell function passes `LIL_HANDOFF=<tmpfile>`; the engine
  writes `run\n<cmd>` or `edit\n<cmd>` there and exits; the function evals it.
  Keep the shell functions tiny and free of `emulate -L` — the command must
  see the user's own options. Without a handoff file (bare `bin/lil`) RUN
  falls back to `$SHELL -c`.
- **The answer screen is frozen.** `tests/golden/*.ans` were generated by the
  original zsh renderer (commit 06c2b3d). `render()` and `AnswerStream` must
  reproduce them byte for byte — including the quirk that empty source lines
  are dropped (zsh `"${(f)text}"`), which is why paragraphs sit flush. The
  deliberate deviations (tables among them) are listed at the top of
  `src/render.mjs`, each with a test. The answer screen uses ONLY the `PAL` 256-colour escapes; truecolor is
  for the transient panel.
- **Everything animated is transient.** The panel lives in `Live`'s redrawable
  region and is gone before the prompt returns; committed lines are permanent.
  Every live line is clipped to the terminal width — a wrapped line breaks the
  cursor arithmetic.
- **The panel shows real events only.** Mood, speech, ticker, tool rows and
  the pulse are all driven by pi's JSON stream. Do not add timers that fake
  progress.
- **Isolation**: `PI_CODING_AGENT_DIR=<repo>/pi` keeps Lil Buddy away from a
  user's main `~/.pi/agent`. Never write to `~/.pi/agent/`.
- **Snapshot-at-invocation**: clipboard/terminal are captured *before* pi
  starts. The extension tools only read those files via `$LIL_RUNTIME`, which
  `pi.mjs` exports into pi's environment.
- **Answer contract**: the persona (pi/SYSTEM.md) must emit at most ONE
  ` ```lilcmd ` fenced block, always last. `lilcmd.mjs` takes the LAST block
  and also tolerates `<lilcmd>…</lilcmd>` tags (multi-line or one line), which
  DeepSeek emits in the wild. `AnswerStream` holds a block back while
  streaming. If you change the contract, change both sides.
- **Invocation is `--mode json`**: pi's stdin must be closed (`stdio:
  ["ignore", …]`) — json mode blocks forever on an open non-tty stdin. Split
  the JSONL on LF only (pi's docs: `readline` is wrong for this stream). The
  prompt is a bare positional — never `-- prompt`: pi 0.82 rejects the
  separator. A question starting with `-` gets a leading space instead. Provider usage often arrives only when a response completes; the
  token counter estimates until then.
- **He looks, the human decides — enforced at the tool layer, twice**:
  `--exclude-tools bash,edit,write` on the CLI AND `pi.setActiveTools([read,
  probe, read_clipboard, read_terminal])` on session_start in the extension.
  The `probe` tool (pi/probe-guard.ts) has three tiers: **allow** (a read-only
  allowlist, each command narrowed to read-only flags/subcommands, plus
  `<tool> --version|--help|-V`), **ask** (everything else: runs only after the
  human approves that exact command), **deny** (`sudo`). Probes run under
  `/bin/sh` — never zsh, whose `=(…)` and glob qualifiers can execute code a
  text guard cannot see. Persona promises are flavor, the guard is the
  enforcement. Never re-enable bash/edit/write; a command is "ask" unless
  proven read-only; when extending the allowlist, add a case to
  `tests/probe-guard.test.mjs` for every way the new command can write.
- **Approval is a file handshake**: pi's stdin is closed, so the tool drops
  `<id>.req` in `$LIL_ASK_DIR` (`$LIL_RUNTIME/ask`) and polls for `<id>.ans`;
  `app.mjs` shows the command above the panel and writes `yes` only on an
  explicit `y`. The engine sets `LIL_ASK_DIR` only when someone can answer
  (interactive tty, motion on); otherwise "ask" degrades to BLOCKED. Time
  spent waiting on the human is added back to the run's timeout.
- **Sayings**: random lines from a rotating pool (`~/.cache/lil/sayings.txt`,
  seeded from the repo's `sayings.txt`) replace a stage message once it has
  locked and dwelt 2s; every 5th run a detached child refreshes the pool via
  the DeepSeek chat API (`sayings.mjs --refresh`, never waited on).
- **Self-update** (`update.mjs`): at most daily, a detached child fetches
  `origin/main` and `merge --ff-only`s the checkout — only when on `main` with
  no modified tracked files. Never waited on; every other case is a logged
  skip. It must stay forward-only: no reset, rebase, stash or checkout.
- **Model quirk**: deepseek-v4-flash's thinkingLevelMap offers only high/max —
  don't set a lower defaultThinkingLevel, pi will reject it.
- **Cmd-key chords**: ⌘Enter/⌘C work only via the WezTerm snippet
  (`integrations/wezterm-lil.lua`), which checks the `LIL_SCRATCHPAD` user-var
  (OSC 1337, tmux-passthrough-wrapped). They resolve to the same bytes as the
  always-available keys: `^R` (0x12) run, `^Y` (0x19) copy. The hint row only
  advertises the chords on macOS.

## File map

| Path | Owns |
|---|---|
| `src/` | the engine (see the tree above) |
| `shell/lil.{zsh,bash,fish}` | per-shell function: launch the engine, carry out the handoff |
| `bin/lil` | POSIX launcher for other shells and scripts |
| `lil.zsh`, `install.zsh` | back-compat shims for installs made by the zsh-only version |
| `install.sh` | POSIX-sh installer: deps, shell wiring, `--uninstall` |
| `pi/SYSTEM.md` | the persona (voice + answer contract) — taste-bearing, edit deliberately |
| `pi/models.json` | deepseek provider; `apiKey` MUST stay `"$DEEPSEEK_API_KEY"` (env form), never a literal |
| `pi/settings.json` | defaultProvider/defaultModel/defaultThinkingLevel |
| `pi/extensions/lil-context.ts` | `read_clipboard` / `read_terminal` / `probe` tools, pins the tool surface |
| `pi/probe-guard.ts` | the read-only guard (pure, unit-tested) |
| `integrations/wezterm-lil.lua` | Cmd-chord enhancement snippet (user pastes into wezterm.lua) |
| `sayings.txt` | seed sayings pool |
| `tests/golden/` | answer-screen renders from the zsh original — do not regenerate casually |
| `tests/fake-pi.mjs` | stand-in pi binary for tests (`LIL_PI_BIN`) |

pi runtime droppings inside `pi/` (sessions/, caches, auth.json) are gitignored —
never commit them.

## Environment ground truth

- pi 0.82.1 through 1.6.1 (`@earendil-works/pi-coding-agent`; 1.6.1 needs
  Node ≥ 22.19). Flags this repo relies on: `--mode json`, `-nc`,
  `--exclude-tools`, `--session`, `--append-system-prompt`, and
  `PI_CODING_AGENT_DIR` — all present in both. Check any new flag against the
  oldest version before using it. Verified
  2026-11-25 on Linux against a local OpenAI-compatible mock: extension loads,
  tool surface is exactly `read, read_clipboard, read_terminal, probe`.
- The engine itself only needs Node ≥ 20 and no packages. Do not add npm
  dependencies; `install.sh` assumes there is nothing to `npm install`.
- Kitty keyboard protocol is NOT reliable inside tmux — do not build on it.
- zsh on macOS, bash on most Linux, fish anywhere: test all three
  (`tests/shells.test.mjs` skips shells that are not installed).

## Conventions

- Conventional commits (`feat:` `fix:` `docs:` `chore:`); body says *why*.
- Smallest diff that meets the acceptance criteria; note spotted improvements,
  don't fold them in.
- Persona edits (pi/SYSTEM.md) are taste work: keep the voice punchy,
  one gag max per answer, accuracy outranks charm.
- UI copy is in the house voice: caps for system stamps (`AWAITING ORDERS`),
  "boss" sparingly, never apologetic.

## Verification quick-battery

```sh
npm test                                  # everything that can run headless
node tests/probe-guard.test.mjs           # guard table on its own
lil --demo port                           # the full experience, no key needed
lil --demo danger ; lil --demo blocked ; lil --demo error
LIL_MOTION=compact lil --demo port        # the one-line fallback
lil --doctor                              # this machine
# real pi, isolated config, model present
PI_CODING_AGENT_DIR=$PWD/pi pi --list-models | head -20
# live smoke, non-interactive (plain output, no keys)
lil 'what does lsof -i do, one liner' < /dev/null | cat
```

Interactive keys can be exercised headlessly by driving the CLI in a pty (send
`r`, `c`, `\x05`, Esc), but WezTerm ⌘ chords and real clipboard managers can
only be verified by a human — report them "implemented, unverified
interactively" unless actually exercised.
